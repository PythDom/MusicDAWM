# Decisions

Each entry records a choice the brief left open, why it was made, and whether the user still has to confirm it.
The rule from the brief applies: when a requirement is ambiguous, pick the option closest to the Korg Sound On Sound workflow.

| # | Date | Decision | Why | Status |
|---|---|---|---|---|
| D-001 | 2026-10-22 | **Base on Ardour 9.8, not 9.7.** | 9.8 (tag `9.8`, commit `22ed8656`, 2026-08-19) is the latest stable release and came out after the brief's comparison. The brief says to rebase on Ardour releases anyway, so starting on the newest one saves a rebase. Nothing in the brief depends on 9.7 specifically. | Decided (user, 2026-10-23: "use the most efficient and reliable") |
| D-002 | 2026-10-22 | **Option A (Ardour fork) confirmed.** | Phase 0 found no blocker that would make ARA2 in Ardour infeasible within 3 months (see `PHASE0.md` §3). Ardour 9's per-region plugin chain (*Region FX*) is a close match to ARA's playback-region model. | Decided (user answers 2026-10-23) |
| D-003 | 2026-10-22 | **Build with `--no-phone-home`.** | Stock Ardour's configure enables "Phone home" (the update/announcement check in `gtk2_ardour/pingback.cc`). The brief forbids telemetry. | Decided (hard rule §7) |
| D-004 | 2026-10-22 | **Brand with `--program-name=MusicDAWM`.** | The user chose the name MusicDAWM. Ardour's build already takes a program name, so branding is a build option rather than a patch. Ardour publishes no trademark policy (checked ardour.org and its forum, 2026-10-23); we do not use Ardour's name or logo as our branding and describe the product as "based on Ardour". | Decided |
| D-005 | 2026-10-22 | **ARA code is a separate, optional build feature (`--ara`), and binaries that include it are distributed under GPLv3.** | The ARA SDK is Apache-2.0. Apache-2.0 is compatible with GPLv3 but not with GPLv2. Ardour is "GPLv2 or later", so a binary that links the ARA SDK can only be distributed under GPLv3. Our new code stays GPLv2-or-later, as the brief asks. | Decided (user: "OK", 2026-10-23) |
| D-006 | 2026-10-22 | **Repository layout (proposed for WP1):** import Ardour's full history into this repository, with upstream `9.8` as the base. Our work goes on topic branches, one per WP, and is rebased onto each new Ardour release. Planning documents stay at the top level. | Full history makes merging new Ardour releases easy. A vendored tarball would lose that. Done by `ci/import-ardour-history.sh` in GitHub Actions (the push is about 210 MB). | Decided (user: "yes, if possible") |
| D-007 | 2026-10-23 | **Windows builds run natively in MSYS2 (UCRT64) on GitHub Actions.** Ardour's official MinGW cross-build stays an option. | The official tooling (`ardour-build-tools/win/x-mingw.sh`) lives on `git.ardour.org`, which this cloud environment's network policy blocks. The MSYS2 build works end to end (PHASE0.md §2.2) and needs one small upstream patch (0003). Trade-off: we depend on MSYS2's package versions (GCC 16; PortAudio host APIs and ASIO support not yet checked) instead of Ardour's pinned stack. | Decided (2026-10-23): Ardour's current Windows build tooling (`ardour-build-tools`) is **not public**; git.ardour.org lists only `ardour`, `ardour-tutorial`, `livetrax` and `manual`, and the last public copy of the script dates from 2014. The MSYS2 build is the only reproducible route. |
| D-008 | 2026-10-23 | **Build with `--cxx17` on Windows.** | MSYS2's GCC 16 defaults to C++20, which Ardour 9.8 does not compile under. Ardour already has the option, and macOS builds use it. | Decided |
| D-009 | 2026-10-23 | **Windows only, as a portable folder (zip), no installer.** Linux builds are not shipped. | User's answer. Linux CI stays, because it is the fastest place to run the unit tests and the Mother smoke test (40 min against almost 2 h on Windows). | Decided |
| D-010 | 2026-10-23 | **No "upstream first".** The fork carries its own changes; nothing is posted to Ardour's tracker or forum on the user's behalf. | Ardour's development page: "if you use an LLM (Claude, Codex, CoPilot etc.) to create code, it cannot be included in Ardour", because LLM-generated code cannot be copyrighted in the USA (Thaler v. Perlmutter, March 2025) and the GPL relies on copyright. Ardour's forum terms also forbid posting LLM-generated material. This replaces the brief's rule "prefer changes that could be upstreamed". The user may still report bugs to Ardour in their own words. Every commit in this repository carries a Claude co-author trailer, so the origin of the code is never hidden. | Decided; **user should know the copyright implication** (see PHASE0.md §4) |
| D-011 | 2026-10-23 | **Bundled drum kit: AVL Drumkits, played by the x42-avldrums LV2 plugin.** | AVL kits are CC-BY-SA 3.0 and say music made with them needs no attribution. DrumGizmo kits (CC-BY 4.0) require a credit in any released song that credits performers. Ardour's own Windows packaging already bundles x42-avldrums. | Proposed for WP3 |
| D-012 | 2026-10-23 | **Melodyne essential 5.4.2 is the ARA test target.** | User's edition. Celemony lists essential as working "under ARA". It edits monophonic material only: vocals and single-note guitar lines, not chords. | Decided |
| D-013 | 2026-10-23 | **Windows GUI fonts: use the fontconfig backend (`PANGOCAIRO_BACKEND=fc`) and ship fontconfig's `etc/fonts`.** | Under Wine, MSYS2's Pango did not see Ardour's own fonts registered through GDI (button labels came out garbled). With fontconfig and its config files, they render correctly. Must be confirmed on real Windows. | Proposed for WP1 |
| D-014 | 2026-10-23 | **Version scheme:** MusicDAWM `MAJOR.MINOR.PATCH` in the top-level `VERSION` file (starting at 0.1.0; 1.0 after the final acceptance test). Ardour's own version (from `git describe`, e.g. 9.8.30) is left untouched. | Ardour's version drives session compatibility and the settings folder name, so it must stay Ardour's. The About dialog shows both. | Decided (WP1) |
| D-015 | 2026-10-23 | **Release process:** the `Windows build` workflow, run by hand with "publish", builds the commit, runs the smoke test and creates GitHub release `v<VERSION>` with `MusicDAWM-<VERSION>-win64.zip`. See `docs/releasing.md`. | Brief S3 asks the fork to keep a release process. Tags cannot be pushed from the cloud session, so GitHub creates the tag when it creates the release. | Decided (WP1) |
| D-016 | 2026-10-23 | **Branding keeps Ardour's credits.** New name, icon and splash (own artwork, `tools/branding/`); the About dialog says "a modified version of Ardour" and keeps Ardour's authors, licence and website. The donation dialog after export stays, titled "Support Ardour Development" instead of the program name. Help → Report a Bug points to MusicDAWM's issues. | GPLv2 §2(a)/(c): modified versions must say so. The donation request is honest only if it names who receives the money; sending MusicDAWM bugs to Ardour's tracker would burden Ardour with problems that may be ours. | Decided (WP1) |
| D-017 | 2026-10-23 | **No crash reporter, no telemetry.** Dr. MinGW crash dumps are off (`--no-dr-mingw`), the announcement and update check is compiled out (`--no-phone-home`). | Brief WP1 ("crash reporting off by default") and §7 ("no telemetry"). Nothing else in Ardour contacts the network without a user action (checked 2026-10-23: the other network calls are in user-started features: Freesound search, the video timeline's local video server, clip-library downloads, SoundCloud upload and Lua scripts). | Decided (WP1) |
